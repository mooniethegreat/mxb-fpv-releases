# v1.1 network, rider view and map changes

The user's regression report is authoritative runtime feedback: remote drones
worked before the spectator/map changes, and failed in v1.0 even side by side.
`peer_sync.cpp` and `rider_visuals.cpp` were unchanged between 0.6 and 1.0. That
narrows the suspect area to lifecycle/view integration, rather than establishing
that the wire protocol itself changed. No live game process was attached to,
inspected, patched or launched during this work. Files in the installation were
only read for version, configuration and log context.

## Rider visibility and update priority

Static evidence from the previously saved beta21e snapshot:

- Client sender RVA **2A3350** serializes opcode 28, clock, observer entity ID at
  **5A2004**, then six observer position/velocity floats at **5A2008** before the
  independent vehicle snapshots. Evidence
  `ev_1f817978944763e992b606f079c7e301dd2c41e6451f51bb52fb60e5e9e25ced`.
- Server receiver RVA **29F1E0**, opcode 28, reads that observer into connection
  fields **+BA8** (entity) and **+BAC..BC0** (six floats). Evidence
  `ev_78d837998d157815461fc1ec4e7460031dca41da569e9850bde4d1d8a0b815bc`.
- Server priority RVA **29C760** uses the selected entity's position when its ID
  is nonzero; otherwise it uses the independent observer coordinates to order
  riders by distance. Evidence
  `ev_0aeeefdaab6b0adb9d30c3a9800f43921faf472b466be31ccf95ce21005e7623`.
- Entity playback RVA **2AA7E0** returns failure when its two selected snapshots
  are more than 0.3 seconds apart. The exact compare at **2AA8CB** is
  `66 44 0f 2f 05 bc 94 0a 00`. Evidence
  `ev_13afecef3e1630b5f1178dd0aea717044a84755ed4c25cce4a136e2bca9598b7`.

Implementation: a signature-checked sender hook overrides only the observer for
the duration of serialization, then restores its 28 bytes. It never overwrites
the authoritative vehicle stream. A separate signature-checked compare points to
an aligned owned value near the instruction; the shared game constant is untouched.
The owned value is 2.0 seconds in FPV and 0.3 otherwise. Shutdown restores the
instruction if still owned. A pre-existing modification to the site is left alone.
FrostMod's MIT-licensed findings identified this site; static analysis corroborated it.

Rider graphics RVA **523E0** reads world matrices from a **0x760-byte** render
record, confirmed by render conversion RVA **154A0** and renderer output. Evidence
`ev_386819b62456ebdf978ad282d0d42425a0cbc5041977f5d56e45864974a143b0`.
The remote rider filter works on a private copy, translates the known world
matrices, resets on respawn/teleport/timeout and bounds correction to 2.5 m. It
does not change physics, collisions, input, network state or another client's view.

## Sharing recovery

The native frame and packet layouts remain 108/96 bytes and compatible with the
earlier protocol. A roster-authenticated, bounded, finite, sequenced state now
also establishes capability. Hello/ack packets carry usable state immediately.
Discovery retries within five seconds, and while flying a 2 Hz state bootstrap
repairs a missing handshake; confirmed peers receive 20 Hz flight updates. A
changed local logical connection resets the prior peer generation. Byte-sized
connection IDs are accepted without the old artificial signed-127 ceiling.

Remote pose interpolation uses local arrival times, a configurable 100 ms buffer,
shortest-arc quaternion interpolation and at most 75 ms prediction. Teleports and
flight-state transitions clear history; stale states still expire. Every consumer
uses the same peer snapshot. The settings/log status includes confirmed/flying
peer counts and TX/RX/recovery counters so future failures leave useful evidence.

This is a recovery fix, not a claim that static analysis reproduced the user's
two-client failure. Public-server gameplay verification remains the user's work.

## MaxHUD integration

The supplied MaxHUD_MXB64.dlo SHA256 is
`d6216e38d3b8100ce34dbf83b18e075d320c7c05c497147dfb8f626da0118295`.
The optional adapter requires that exact file hash before reading private fields.
No MaxHUD file is modified or shipped.

- Manager pointer **+48A68**, widget vector **+190/+198**, HUDMap vtable **+37D38**.
  Constructor evidence `ev_3be2a2b6d73831ba55d9112255ec2d4f0f6f8b5be1788bd2ef77f156643293c0`.
- Map callback **+C3B0** applies the current rotation, center and optional range.
  Evidence `ev_cadbc39a84d673f8519337b5ec23c4cca8a296e7914b25162f28b99dc2302e7b`.
- Pure axis projections **+E200/+E300** read the current map world bounds, line
  padding, size and position. Evidence
  `ev_4a89b6209dd348ae3de254bda45ef3aa7eb64588cbe991de1f90f829868f621a`
  and `ev_aa0041105bd5cb2c4b2fbba65137592c242f853c948de1ec33415e25faa5a908`.

The adapter samples an affine projection and matches the unique background sprite
to the final returned SDK quad, observing the actual viewport conversion. It works
without three noncollinear riders or rider labels. SDK quad coordinates span the
full window; the previous guessed 4:3 conversion was removed. When MaxHUD's map is
present, the overlay draws only drone icons, never another track/background/rider
layer. Other HUD plugins are not intercepted.

Selected evidence is retained under `research/mxbikes-local` and `research/maxhud`
in the private workspace; binaries and decompiler output are excluded from releases.
